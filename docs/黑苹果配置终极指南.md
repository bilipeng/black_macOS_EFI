## 二、磁盘布局与非标准 ESP（重要）

| 盘 | 分区 | 说明 |
|---|---|---|
| disk0（1TB 西数，装 macOS） | disk0s1 MSR 16.8MB / disk0s2 673GB(NTFS) / **disk0s3「EFI」313.5MB（类型写的是 Microsoft Basic Data，FAT32，OC 就在这里）** / disk0s4 Apple_APFS（容器 disk2，系统在 disk2s4） | 512G 盘装 Windows，其 ESP 太小无法扩容，所以**在 macOS 盘上自建 EFI 并映射给固件**实现 OC 引导 |
| disk1（512GB Intel，装 Windows） | disk1s1「NO NAME」104.9MB 真正 EFI（含 `EFI/Microsoft/Boot/bootmgfw.efi`） | Windows 自己的引导分区 |

> ⚠️ **风险提示**：OC 所在分区类型不是标准 ESP GUID，且 `Misc:Boot:LauncherOption = Disabled`。
> 若 Windows 更新重置 NVRAM 启动项，OC 可能被绕过。出问题时先检查 BIOS 启动顺序，
> 必要时用 `bless` 重新指定启动项（见 §12）。

### 3.1 ACPI 各文件作用

| 文件 | 作用 |
|---|---|
| `SSDT-PLUG-ALT.aml` | CPU 电源管理，注入 `plugin-type=1` 让 XCPM 接管（变频必需） |
| `SSDT-EC.aml` | 伪造 Embedded Controller，让 AppleACPIEC 能挂载（笔记本必需） |
| `SSDT-SBUS.aml` | 补 `SMBus`/`SBUS` 设备，苹果 SMBus 驱动依赖它 |
| `SSDT-MCHC.aml` | 补 `MCHC` 内存控制器设备，缺它会导致睡眠异常 |
| `SSDT-GPI0.aml` | 补 I2C 触摸板所需的 `GPI0` 设备 |
| `SSDT-RTCAWAC.aml` | RTC/AWAC 时钟设备修正 |
| `SSDT-USB-Reset.aml` | USB 端口重置（配合 USBMap） |
| `SSDT-USBX.aml` | 注入 USB 供电参数（电流/电压），影响外设供电与充电 |
| `SSDT-XOSI.aml` | 把 `_OSI` 伪装成 Windows，部分 DSDT 分支依赖 |

### 3.2 UEFI 驱动各文件作用

| 文件 | 作用 |
|---|---|
| `OpenRuntime.efi` | OC 必需，提供 Runtime Services（NVRAM、内存映射） |
| `HfsPlus.efi` | 读取 HFS+ 卷（安装 U 盘/恢复分区） |
| `apfs_aligned.efi` | APFS 驱动（对齐版本），读 macOS 卷 |
| `OpenCanopy.efi` | 图形化启动菜单（读取 Resources 图标） |
| `ResetNvramEntry.efi` | 菜单里提供「Reset NVRAM」入口 |
| `UsbMouseDxe.efi` | 启动菜单支持鼠标操作 |
| `Tools/NullMothSafe.efi` | N 卡驱动注入工具 |

> **版本铁律**：OpenCanopy.efi、OpenRuntime.efi、apfs_aligned.efi 等 OC 自带驱动
> 必须与 OpenCore 主程序**同版本**，混用可能导致无法启动。

## 四、关键 config 设置

### 4.1 boot-args（当前实机值，2026-11-16 最终版）

```
-vi2c-force-polling -ibtcompatbeta revpatch=sbvmm,cpuname -amfipassbeta alcid=70 nvrmacpibl=1 nvfb=1 nvaccel=1 nvfbheads=2 -nvkmsnosmooth amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0 gfxrst=4
```

| 参数 | 作用 |
|---|---|
| `alcid=70` | AppleALC 布局号，ALC256 用 70 |
| `-vi2c-force-polling` | VoodooI2C 强制轮询，I2C 触摸板中断不稳时的兜底 |
| `-ibtcompatbeta` | Intel 蓝牙兼容 beta 系统 |
| `revpatch=sbvmm,cpuname` | RestrictEvents：屏蔽「不支持机型」提示、伪装 CPU 名称 |
| `-amfipassbeta` / `amfi=0x80` / `amfi_get_out_of_my_way=0x1` | 放宽 AMFI 签名校验，允许第三方 kext（配 AMFIPass） |
| `nvrmacpibl=1 nvfb=1 nvaccel=1` | NVIDIA 社区驱动：帧缓冲、加速、背光 |
| `nvfbheads=2` | 显示输出头数量（从 4 改为 2，减少显示器面板枚举卡顿） |
| `-nvkmsnosmooth` | 关闭 NVIDIA KMS 平滑，减少画面撕裂/卡顿 |
| `ipc_control_port_options=0` | 关闭部分 IPC 限制 |
| `gfxrst=4` | 显卡复位策略（若唤醒黑屏可尝试调整此值） |

> **已移除的调试参数**：`keepsyms=1`、`-vsmcdbg`、`-alcdebug`、`-liludbg`。
> 它们会持续写内核追踪日志（实测约 1MB/5秒）造成隐性卡顿。排错需要时临时加回，稳定后务必移除。

### 4.2 Kernel 关键项

| 项 | 值/内容 | 说明 |
|---|---|---|
| `Kernel:Block` | `com.apple.iokit.IONDRVSupport`、`com.apple.iokit.IOSkywalkFamily`（均 Enabled） | 屏蔽原生 kext，给 NVIDIA 与 Intel Wi-Fi 的替换件让路 |
| `Kernel:Emulate` | `Cpuid1Data = 55060A00…`、`Cpuid1Mask` | CPU 伪装，i7-13700H 对应 CPUID |
| `AppleXcpmCfgLock` | True | 绕过 CFG Lock 未解锁导致的内核 panic |
| `CustomSMBIOSGuid` | True | 只对 macOS 用自定义 SMBIOS（双系统必需） |
| `DisableIoMapper` | True | 关闭 VT-d 映射 |
| `DisableLinkeditJettison` | True | Lilu 稳定运行前提 |
| `PanicNoKextDump` / `PowerTimeoutKernelPanic` / `ProvideCurrentCpuInfo` | True | 13 代 CPU 必需；后者让内核正确读取大小核信息 |
| `XhciPortLimit` | False | 已用 USBMap 端口映射，不需要放开 15 端口限制 |

其它已开启的 Kernel Quirks：`SetApfsTrimTimeout=-1`
Booter Quirks：`AllowRelocationBlock`、`AvoidRuntimeDefrag`、`EnableSafeModeSlide`、
`FixupAppleEfiImages`、`ProtectUefiServices`、`ProvideCustomSlide`、`RebuildAppleMemoryMap`、
`SetupVirtualMap`、`SyncRuntimePermissions`（全部 True，缺一可能影响启动）

### 4.3 DeviceProperties（3 条，关键）

| 设备路径 | 属性 | 说明 |
|---|---|---|
| `PciRoot(0x0)/Pci(0x1,0x0)/Pci(0x0,0x0)` | `NVRMFBDisplayAudioCodecInfo = 00010400`、`acpi-wake-type = 1` | NVIDIA 帧缓冲的 HDMI/DP 音频 codec 描述 + 唤醒方式 |

## 六、声卡完整解决方案（本次修复核心）

### 6.1 症状与判定

- 系统里完全没有音频设备：`system_profiler SPAudioDataType` 的 `Devices:` 为空
- `ioreg -c AppleHDADriver -r -l -w0` → `!registered, !matched`（start 失败）
- `ioreg` 里 `IOAudioEngine` / `IOAudioDevice` 数量为 0
- 日志里可能看到 `RequestResource`、`Unable to create bundle`

### 6.2 病因（一句话）

AppleHDA 在 `SystemKernelExtensions.kc` 里记录的 bundle 路径被写成
`/System/Volumes/Update/mnt1/System/Library/Extensions/AppleHDA.kext`（临时更新目录），
而 AppleALC 的运行时资源替换面向 `/System/Library/Extensions`。
两者不是同一位置 → AppleHDA 读到苹果原版 `layout7`（别的机型节点图），
套上 ALC256 的 pin 配置后节点不匹配 → 驱动 start 失败 → 全系统 0 个音频设备。

**这不是布局选错。** `IOAudioDeviceModelID = "AppleHDA:7"` 是正常现象（AppleALC 把自定义布局挂靠到平台槽 7），
真正的布局看 `alc-layout-id` 与 `AppleHDACodecGeneric` 的 `HDAConfigDefault`
（应为 `CodecID=283902550`、`LayoutID=7`、注释名含 `ALC256`、`alc-pinconfig-status=Yes`）。

### 6.3 修复三步（缺一不可）

```bash
# 前提：把干净的 AppleHDA.kext（600.2）放进 /System/Library/Extensions，owner root:wheel

# ① 可写挂载系统卷（根卷只读密封，不能直接改）
mount_apfs -o rw,nobrowse /dev/disk2s4 /System/Volumes/Update/mnt1
# 设备号用 mount | grep ' on / ' 里的那个 APFS 卷（去掉末尾 s1）

# ② 重建系统内核集合（关键在 -p）
kmutil create -n sys -R / \
  -B /System/Library/KernelCollections/BootKernelExtensions.kc \
  -S /tmp/SystemKernelExtensions.kc \
  --kdk /Library/Developer/KDKs/KDK_26.7.2_25G332.kdk \
  -p /System/Library/Extensions/AppleHDA.kext -z
# 把产物拷进系统卷的 System/Library/KernelCollections/，chown root:wheel、chmod 755，然后卸载

# ③ 重建启动快照并指向它（--bootefi 必须加）
mount_apfs -o rw,nobrowse /dev/disk2s4 /System/Volumes/Update/mnt1
bless --folder /System/Volumes/Update/mnt1/System/Library/CoreServices \
      --bootefi --create-snapshot
umount /System/Volumes/Update/mnt1
# 返回 0 后新快照标成 "Will root to (boot from) this snapshot"，然后重启
```

> 桌面 `EFI_work/` 里有三个已写好的脚本可直接用：
> `step1_restore_applehda_path.sh`、`step2_install_kc.sh`、`step3_bless_snapshot.sh`。

### 6.4 三个必踩的坑（实机踩过）

| 坑 | 报错 | 真相 | 解法 |
|---|---|---|---|
| KDK 目录里有重复软链 | `Missing Developer Kit: ... matching your build 25G332`（哪怕版本/UUID/回执全对） | kmutil 扫到两个同 build 的 KDK，判定无唯一匹配 | 只留一个 KDK 目录；`CurrentKDK` 别名允许 |
| 忘了 `-p` | 打出的 KC 里 **0 条 AppleHDA** | 给了 `--kdk` 后 kmutil 只从 KDK 清单取件，而 KDK 里本来没有 AppleHDA | 必须 `-p /System/Library/Extensions/AppleHDA.kext` 显式点名 |
| 忘了 `--bootefi` | `Can't use snapshot options without --bootefi` | 根卷走密封快照引导，只写文件不改快照 = 重启仍读旧的 | `bless --folder … --bootefi --create-snapshot` |

### 6.5 判定是否真修好

```bash
strings -a /System/Library/KernelCollections/SystemKernelExtensions.kc | grep -c Update/mnt1   # 必须 0
ioreg -c AppleHDADriver -r -l -w0 | grep -E "registered"                                      # 必须 registered, matched
system_profiler SPAudioDataType                                                               # 必须出现 Devices
```

正常输出应包含：

```
Built-in Microphone   2ch   Default Input Device
Built-in Output       2ch   Default Output Device
alc-pinconfig-status = Yes
```

## 七、其余驱动解决方案逐项说明

### 7.1 显卡（RTX 4060 Laptop）

- **思路**：`WhateverGreen` + 社区 NVIDIA 驱动（`NVRM`/`NVAccel`/`NVRMAGDC`/`NVRMFB` 装在 `/L/E`）
  + `nvfb=1 nvaccel=1 nvrmacpibl=1` + `-nvkmsnosmooth` + `Tools/NullMothSafe.efi` 引导注入
- **Block**：屏蔽 `com.apple.iokit.IONDRVSupport`，避免与 NVIDIA 帧缓冲冲突
- **DeviceProperties**：`NVRMFBDisplayAudioCodecInfo`、`acpi-wake-type`
- **现状**：内屏 2560×1600 正常，Metal 3 可用；实测 GPU 56°C、占用 32%
- ⚠️ 驱动来源属社区移植，升级前先确认与 26.x 的兼容性

### 7.2 无线（Intel Wi-Fi）

Sonoma 之后苹果删了旧 802.11 框架，需要三件套 + Block：

1. `Kernel:Block` 加 `com.apple.iokit.IOSkywalkFamily`
2. 注入 `IOSkywalkFamily.kext`（第三方替换件）
3. 注入 `IO80211FamilyLegacy.kext` + `AirPortBrcmNIC.kext`
4. 注入 `AirportItlwm.kext`（Intel 网卡主驱动，走原生 Airport 栈）

`itlwm.kext`（私有栈版本）作为备选保持 OFF。
三件套 kext 都设了 `MinKernel=23.0.0 / MaxKernel=25.99.99`。

> ⚠️ **升级 macOS 前必须先更新这套网卡驱动，否则 Wi-Fi 失效。**

### 7.3 蓝牙（Intel）

`IntelBluetoothFirmware` + `IntelBTPatcher` + `BlueToolFixup`，加 boot-arg `-ibtcompatbeta`。
不需要 BrcmPatchRAM 系列（那是博通方案）。

### 7.4 触摸板（I2C）与键盘（PS2）

- I2C 链路：`RaptorLakeI2C` → `VoodooI2C`（+ `VoodooGPIO`、`VoodooI2CServices`）→ `VoodooI2CHID` → `VoodooInput`
- boot-arg `-vi2c-force-polling` 保证中断不稳时仍能工作
- PS2 兜底：`VoodooPS2Controller` + Keyboard/Mouse/Trackpad
- ⚠️ 两份 `VoodooInput` 只能有一份启用（PS2 内那份已 OFF）

### 7.5 电池、传感器、风扇

`VirtualSMC` + `SMCBatteryManager`（电量）+ `SMCProcessor`（CPU 温度）+ `SMCSuperIO`（风扇）
+ `ECEnabler`（读 8 位以上 EC 字段）+ `SSDT-EC` + DeviceProperties 里那 4 组 `fan*-addr/size`。

### 7.6 CPU（13 代大小核）

`CpuTopologyRebuild.kext` 伪装拓扑，让 6P+8E 在 macOS 下被正确调度；
`ProvideCurrentCpuInfo=True` 让内核读对 CPU 信息；`SSDT-PLUG-ALT` 给 XCPM 接管；
`Kernel:Emulate` 用 `Cpuid1Data/Cpuid1Mask` 伪装 CPUID。
实测变频正常（powermetrics 显示核心频率在 492~2088MHz 间动态波动）。

### 7.7 硬盘与有线网卡

- `NVMeFix.kext`：NVMe 电源管理
- `RealtekRTL8111.kext`：有线网卡，实测正常

### 7.8 USB

`USBToolBox.kext` + `USBMap.kext`（本机实测端口表）+ `XHCI-unsupported.kext`
+ `SSDT-USBX`（供电）+ `SSDT-USB-Reset`。`XhciPortLimit=False`（已用映射，不再放开 15 端口限制）。
USBMap 对睡眠唤醒稳定很关键，重装务必保留。

### 7.9 亮度

`BrightnessKeys.kext` 提供快捷键调亮度（PWM 走 WhateverGreen/NVIDIA 那份）。

### 7.10 已移除 / 未采用的项

- `SMCLightSensor.kext` 已于 2026-11-16 移除（本机无环境光传感器，会导致「显示器」设置面板查原彩时超时卡顿）；
  同时 `nvfbheads` 从 4 改为 **2**。
- 键盘 RGB 颜色控制：亮度走标准背光接口可用，颜色走机械革命私有 EC 命令，macOS 无对应软件，未实现。
- AirDrop（隔空投送）：社区 ForbiddenItlwm 项目可实现，但为 AI 辅助编写 alpha 版、有内核崩溃风险，未采用。
